## 5. Manifest Validation

Before relying on this manifest, an executing prompt shall compare every required listed artefact with the metadata inside the actual controlled file.

The result shall be one of:

| Result | Meaning | Treatment |
|---|---|---|
| Aligned | Manifest and controlled artefact agree | Continue without repeating full baseline discovery in the user-facing output. |
| Expected pending update | A human-approved candidate is being applied or regenerated in the current controlled workflow | Use the explicitly supplied approved candidate, identify the temporary difference and produce the required manifest update in the same review package. |
| Drift | The manifest and controlled artefact disagree without an explained current workflow | Stop before generation that depends on the disputed baseline and report the exact mismatch. |
| Missing | A required manifest entry or controlled artefact is unavailable | Report the missing authority and do not infer its contents. |

Validation shall compare:

- Document ID;
- controlled filename;
- internal version;
- status; and
- applicability to the requested operation.

## 6. Maintenance Rule

HJ-000 is updated only when a controlled baseline artefact is added, removed, renamed, versioned or changes status.

- PR-007 shall include an HJ-000 candidate when its propagation batch changes any indexed baseline entry.
- PR-002, PR-004 and PR-005 shall include an HJ-000 candidate alongside their generated artefact when human approval will change an indexed version or status.
- PR-006 shall not update HJ-000 for ordinary source-code or test-code stages because implementation files are not indexed here.
- An approval comment alone does not require regeneration of unchanged content. Where the approved candidate already contains the intended version and status, only the manifest entry requires synchronization.
- HJ-000 changes never approve the target artefact and never substitute for its human approval gate.
